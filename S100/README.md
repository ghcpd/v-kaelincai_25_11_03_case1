# 🧪 Evaluation of GPT-5-Codex, GPT-5, Claude Sonnet 4.5, S100, and S40 on Feature & Improvement – New Feature

## 📘 Overview
This repository compares two implementations of the **Smart Permission Aggregation** feature. The feature computes the effective allow/deny decisions for enterprise support engineers by merging direct grants, group memberships, role templates, and environment constraints. The experiment evaluates how quickly and correctly each implementation delivers the new capability, focusing on:

- ✅ Functional correctness across normal, stress, and malformed payloads
- ⚙️ Optimization of aggregation time for large replicated inputs
- 🛡️ Robust handling of invalid or suspicious descriptors
- 📈 Automated metric collection (accuracy, coverage, throughput)

## 🧾 Test Scenario & Expected Behaviour
| Case | Category | Description | Expected Outcome |
| --- | --- | --- | --- |
| `basic` | Normal | Direct, group, role grants with suspended action | Allows `comment:kb`, `edit:kb`, `read:kb`, `tag:kb`; denies `delete:kb`, `share:kb` |
| `conflict_resolution` | Normal | Group-level deny overrides direct allow | Allows `override:ops`, `restart:ops`; denies `deploy:ops`, `shutdown:ops` |
| `large_enrollment` | Stress | 400 replicated groups plus roles & constraints | 5 allowed actions including `audit:reports`; denies `delete:reports`, `export:reports`, `share:reports`; optimized evaluator hits ≥80 ops/sec burst |
| `missing_sections` | Invalid | Missing `user.roles` key | Raises `ValueError("Missing required key: user.roles")` |
| `invalid_types` | Invalid | Non-dict `user` field | Raises `ValueError("Payload must include a 'user' object")` |

Structured inputs and reference expectations live in `ProjectA/data/input_data.json` and `ProjectB/data/test_data.json`. Both projects load the same payloads to guarantee comparability.
